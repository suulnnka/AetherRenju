# AetherRenju 小型 NNUE 设计(v0.3 候选,仅设计不实施)

> 状态:**设计文档**。不含任何实现与训练;数字为预算推演,以实测为准。
>
> **决议(2026-09-30):L1-R 定型 h = 16**(38,978 参数,嵌入/PSQ i8、
> 头 i16,wasm 估算 ≈ 58 KB / 70 KB 闸门)。h=20 满配不实施,仅在
> 实测 gzip 熵确认余量后作为升级位重议。
> 背景:v0.2 引擎(Rust → wasm)评估仍是手调五元窗;本文设计一个
> **塞进 70 KB gzip 预算**的学习型评估。参照系是同类开源 NNUE 引擎
> (7.5M 参数 NNUE + codebook)——它的路线放不进预算,本文给出
> 同思想、小三个数量级的版本。

## 0. 约束与预算数学(设计的第一性输入)

| 约束 | 值 | 来源 |
|---|---|---|
| 引擎 wasm gzip 总预算 | ≤ 70 KB | `scripts/check-size.mjs` 闸门 |
| 当前 wasm gzip(v0.2) | 18.4 KB | 实测 |
| 预留给推理代码 + 特征设施 | ~2 KB gz | 估算 |
| **可用于权重的 gzip 预算** | **≤ 49 KB** | 70 − 18.4 − 2 |
| 随机整数量化的压缩率 | i8 ≈ 0.97 B/参数;i4 ≈ 0.55 | 经验值,不可依赖熵 |

⇒ **参数量上限:i8 约 50K,i4 打包约 90K。** 这是整个设计的锚:
词表 × 累加器宽度必须在 5 万参数以内,而不是全量方案的 734 万。

其余硬约束(全部继承 v0.2 工程):

- wasm32 上 no_std、**零动态分配**、全静态区、单线程;
- make/unmake **增量对称更新**(NNUE 的立身之本:评估随走子 O(小));
- **整数推理、确定性**(同输入同输出,节点预算可复现口径不破);
- 与 RENJU 禁手**零耦合**(评估是纯几何,合法性住在走子生成里);
- qsearch 的 CNT 快筛与 tier 排序**继续可用**(不推倒重来)。

## 1. 为什么不是全量 NNUE 方案

全量方案:14,336 稀疏特征 × 512 累加器 = 7.34M 参数仅特征表;
gzip 后权重 1.8 MB。差三个数量级,没有任何压缩能救。但全量方案的
**思想**可以缩:稀疏查表 + 增量累加器 + 小头。关键是把「特征词表」
从手工设计的 14,336 维换成**天然增量**的线段模式词表——v0.2 已经
在增量维护 572 个五元窗的 (b,w) 状态,离「每窗一个精确模式 id」只差
一步,而那一步就是把手工 WSC 表换成可学习嵌入的第一级。

## 2. 总览:三级演进,每级独立可回退

```
L0  学习型线段价值表(线性,2,187 参数)
    └─ 直接替换 WSC 的可学习版;词表与 L1 相同,零结构风险
L1  每格方向码本 NNUE(主设计 L1-R:活跃 919 × 16 × 双向组 + PSQ + 分区头,39K 参数)
    └─ 真 NNUE:每格稀疏查表 → 逐格激活 → 分区池化 → 小头(轻量头)
L2  空间修正(可选模块,按剩余预算加装:PSQ / 分区粗特征)
```

每级有独立的体积/速度/棋力闸门(§9),任何一级不达标就停在上一步。
L0 本身就是有价值的交付物(手工表 → 调优表),L1 失败不影响 L0。

## 3. 特征体系:7 格线段模式

### 3.1 定义

- 所有长度为 7 的连续线段:横 135 + 竖 135 + 两对角各 81 = **432 段**。
- 每段状态 = 7 个格子的三元编码(0 空 / 1 黑 / 2 白):
  `id = Σ s_k · 3^k`,词表 **3^7 = 2187**,u16 可存。
- 取 7 而不是 11:7 = 五连 + 两端各 1,恰好判「开/闭」与
  「断点跳三/跳四」。长窗词表爆炸(3^11 = 177K),且**混色死段占比
  随长度下降**——活跃模式(存在单色 5 子窗者)实测:

  | 窗长 | 词表 | 活跃 | 占比 | h=16 参数 |
  |---|---|---|---|---|
  | 5 | 243 | 63 | 26% | 1,008 |
  | **7** | **2,187** | **919** | **42%** | **14,704** |
  | 9 | 19,683 | 11,047 | 56% | 176,752 ✗ |
  | 11 | 177,147 | 118,519 | 66% | 1.9M ✗ |

  ⇒ **L=7 / h=16 / 活跃 919 行**是 50K 预算的唯一可行甜点;
  死段(混色)嵌入行恒为 0 不存储,id→行映射用 const fn 构建期生成,
  零文件成本。6 格回退版:活跃 511(=2×2^6−1,混色即死),再省 44%。

### 3.2 为什么这个特征是对五元窗的严格升级

当前 (b,w) 计数把 `●●●_●` 与 `●●●●·`、`_●●●_`(开三)与
`●●●__`(闭三)全部混在同一直方图桶里,层次只能靠手调权重硬拉。
精确模式 id 天然区分这些;「跳三是不是威胁」「三的两端开闭」正是
评估里最值钱的信息。同时它是**位置无关**(同 id 同值)——空间性
由 L2 补,这是预算下的明确取舍。

### 3.3 增量维护(v0.2 已有设施的自然延伸)

现有:572 个五元窗按 (b,w) 增量维护(WB/WW/CNT),走子时经
`CW[cell]` 找到受影响窗。新增:

```
SEGID: [u16; 432]        // 每段当前模式 id
SEGOFF: cell → ≤28 项    // (段号, 段内偏移) 对;构建期生成(仿 CW)
DEAD:  [bool; 2187]      // id 是否混色(废段,嵌入行恒为 0)
```

- `make(cell, side)`:`id += (side==黑 ? 1 : 2) · 3^k`,k ∈ 该格在各段的
  偏移(每格至多 7 段/方向 × 4 方向 = **28 段**);`unmake` 减回,精确可逆。
- 累加器 `ACC: [i32; 16]`:每段 id 变化时
  `ACC += E[new_id] − E[old_id]`(DEAD 段跳过,双端都死时零成本)。
- **不需要每 ply 快照**:加/减自逆,单一累加器走到底。

## 4. 网络结构与参数预算

### L0(线性,引导级)

```
eval_black = Σ_432段 V[id]              V ∈ i16[2187]
score(stm) = ±eval_black + tempo
```

- 参数 2,187 × 2B = **4.3 KB**(gzip 后 wasm ≈ 23 KB,几乎无感)。
- 初始化:用手工公式(复刻 WSC 语义:段内最佳五子窗 + 端点开闭加成)
  生成 V₀,使初始评估 ≈ v0.2 —— **上线即可回退到当前强度**。
- 本质:「codebook = 离线预计算的查表」的最小化身。

### L1-R(主设计:每格方向码本 + 分区头,轻量 NNUE)

> 为什么不是全局累加器:把 225 格的空间信息压进一条全局向量,
> 恰是全局池化类方案的第一号瓶颈(「1D 全局 512 维 → 225 格棋盘」)。
> MixNet 类设计的解法是**每格聚合**——
> 50K 预算做得起缩小版,且增量成本与全局累加器同阶。

```
① 每格每向一个中心 7 格窗(距边 <3 的格该向补零向量)
     id[cell][dir] ∈ [0,2187)          900 个,增量维护
② 每格特征向量(横竖用 E_hv,斜向用 E_di —— 边界对称性分组)
     F[cell] = E_{hv/di}[row(id)][h] × 4 向求和
             + P[color][cell][h]        (己子 PSQ,空格不加)
③ 逐格激活后按 3×3 分区池化
     Z[zone][h] = Σ_{cell∈zone} SCReLU(F[cell])    增量维护 9 份
④ 头:concat(Z[9×h]) ⊕ [行棋方, 模式] → 16 SCReLU → 1
     (可选星块:隐层两两相乘的核技巧池化,零额外参数)
score(stm) = ±out + tempo(stm)
```

**参数预算(h = 16,已定型配置):**

| 部件 | 计法 | 参数 |
|---|---|---|
| E_hv(横竖共享) | 919 × 16 | 14,704 |
| E_di(双斜共享) | 919 × 16 | 14,704 |
| P(PSQ,色×格×维) | 2 × 225 × 16 | 7,200 |
| 头 | (9×16+2)×16 + 16 + 16 + 2 | 2,370 |
| **合计** | | **38,978 ≈ 39K / 50K** |

- 体积:i8 存活行 39K 参数 ≈ **38 KB gzip**;wasm 总估算 **≈ 58 KB**
  (余 12 KB 缓冲);
- 满配变体 h=20(参数 48.7K / wasm ≈ 67 KB):**决议不采用**——过闸
  只余 3 KB;若实测压缩熵证明余量充足,作为升级位另行重议;
- 量化:嵌入与 PSQ i8,头 i16,Z 与中间累加 i32 —— 纯整数、确定;
- 备胎链:i4 打包(19 KB)→ h=12(25K 参数)→ 砍 PSQ → L0。

**增量成本(与全局累加器同阶)**:落一子影响每方向 ±3 格的中心窗,
即 ≤28 个 (格,向) id 更新;每个更新做「旧 SCReLU(F) 撤出分区、
新 SCReLU(F) 加入」的差分(h 维):≈ 1.1–1.5K ops/make,与旧 L1 的
28 段 × 2×16 同量级。F[225][16] 常驻内存(14 KB,内存不占文件)。

**边界处理**:距边 <3 的格缺中心窗 → 该向零向量。这不是纯损失——
边格子线少、潜力本来就低,PSQ 承接位置价值;变体「锚定窗」(取包含
该格的最近 7 窗,细胞间重叠不均匀但可学)列为升级位,make 触达升到
≤52 个 (格,向)。

### L2(可选模块,按余量加装,互相独立)

| 模块 | 内容 | 参数(i8) | 作用 |
|---|---|---|---|
| 加宽到 h=20 | 所有部件同步加宽 | +9.7K(合计 48.7K) | 表达力;wasm ≈ 67 KB,已决议不采用(升级位) |
| 锚定窗边界 | 距边 <3 的格取最近包含窗 | +0(复用行) | 补边缘方向信息;make 触达升至 ≤52 |
| 星块头 | 隐层两两乘积池化 | +0 | 核技巧非线性,零参数 |
| STM 双视角 | 黑白各一份特征(HalfKP 式) | ≈×1.7 | 黑绝对视角 + 头部位已够,优先级最低 |

主设计已含 PSQ 与分区池化(合计 39K / wasm ≈ 58 KB,余 12 KB);
L2 是「余量怎么花」的排序,默认只选星块头(零参数)。

## 5. 推理成本分析(最容易翻车的部分)

当前 make ≈ 150 ops(24 邻居 + 20 窗 × ~6),叶评估 O(1) 读数。

| 项 | L1-R 后成本 | 估算 |
|---|---|---|
| make 增量 | ≤28 个(格,向)id 更新 ×(死判 + h 维差分进出分区) | ~1,100–1,500 ops |
| 叶评估 | 头前向 (9×16+2)×16 + 16 | ~2,600 ops |
| 合计 | make ~8–10×,叶评估每叶子一次 | — |

参照:同类 Rust 引擎单线程 30–50 万 NPS 也是这个量级的每节点成本。
预期 v0.3 NPS ≈ v0.2 的 **50–65%**(搜索深度换评估质量)。
**闸门定 ≥ 50%**,低于即回退 L0 或加「废段零更新」类优化。

已有的免费优化:DEAD 跳过(中盘多数段混色后 make 实际触达段数
远小于 28);`SEGOFF` 与 `CW` 同构,代码路径复用。

## 6. 与搜索的集成

- `evaluate()` 改读 `score(stm)`;**WB/WW/CNT 五元窗机制全保留**:
  qsearch 的 O(1) 快筛、tier 排序、point_score 增益全部不动——
  它们要的是「威胁类别」,不是「分值」,与 NNUE 并行不悖。
- make/unmake 同时维护两套增量(窗 + 段),`debugState` 快照测试
  扩展段状态,一致性断言照旧。
- VCT 不受影响(纯几何威胁枚举,不读评估)。
- 权重装载:`include_bytes!("../weights/l1.bin")` + 启动时一次性
  解包到静态区(常量表数据段直接 gzip,不进源码)。

## 7. 可复现性

- 整数推理 ⇒ 同局面同分数 ⇒ 节点预算口径不破(`searchBest` 结果
  逐位可复现的测试继续成立);
- 权重文件带 header:魔数 / 版本 / 词表长度 / H / scale / 校验和,
  ABI 版本号 `ar_version` 同步 +1,worker 侧拒绝不匹配版本(fail-closed);
- 训练产物的生成脚本与随机种子记录进权重文件尾注。

## 8. 训练管线(仅设计;明确不在本轮执行)

1. **数据生成**(仓库内即可跑,无需 GPU):当前引擎自对弈
  (双模式、多档难度混采),每局面记 `(盘面, 轮走方, 模式, 标签)`;
   标签 = 固定节点预算的搜索分为主 + 对局胜负为辅(cp+WDL 混合,
   与全量方案同思想)。目标 ≥ **35 万局面**(参数量的 10 倍,
   吸取同类方案过拟合教训:4.5M 参数配 1.1M 样本仍翻车)。
2. **L0 调优**:2,187 参数的线性回归 / 简单 SGD,**Rust 测试里就能跑**
   (Texel 风格),不需要任何外部依赖。
3. **L1 训练**:外部 PyTorch;蒸馏教师 = L0 + 搜索分;量化感知
   (QAT 或训练后逐行校准),导出 §6 布局的 `.bin`。
4. **验收回路**:每次导出自动跑 §9 三闸门 + 与 v0.2 的固定对局集。

## 9. 验收闸门(每级独立)

| 闸门 | 标准 | 不达标动作 |
|---|---|---|
| 体积 | `npm run size` ≤ 70 KB(wasm gzip) | 降 i4 / 缩词表至 6 格 / 砍 L2 |
| 速度 | bench 中盘 NPS ≥ v0.2 的 50% | DEAD 优化 / 回退 L0 |
| 棋力 | 固定对局集 vs v0.2 ≥ 55%(≥200 局,双模式各半) | 保留 v0.2 评估 |
| 回归 | cargo test + wasm 冒烟全绿(禁手金标准不动物) | 修完再谈 |

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 过拟合 | 参数压在 35K;样本 ≥ 10×;标签混入对局结果;L0/L1 分级验证 |
| 位置无关特征天花板 | L2 的 PSQ 模块显式补空间性;文档明确这是已知上限 |
| 体积超支 | 三级回退:i4 → 6 格词表 → 只上 L0 |
| NPS 跌破闸门 | DEAD 跳过;评估懒物化(qsearch 叶才算头) |
| 双评估维护出 bug | 状态快照对拍测试扩到 SEGID/ACC(与 WB/WW 同一套 fuzz) |

## 11. 里程碑

- **M0**:SEGID/SEGOFF/DEAD 基础设施 + L0(手工公式初始化)——
  强度应与 v0.2 持平(验收:对局集 50%±5%),体积 +4.3 KB;
- **M1**:L0 Texel 调优(仓库内跑)—— 预期小幅增益;
- **M2**:L1-R 每格方向码本 NNUE(**h=16 已定型**,外部训练 + 量化导出)—— 主增益级;
- **M3**:L2 PSQ(按 M2 后余量决定)。

每级都独立可发布、可回退;任何时刻 `git revert` 回 v0.2 评估
只是删一段 make/unmake 代码与一张表。
