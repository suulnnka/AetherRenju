# 26 开局库(开局名 + 前三手开局策略)

引擎内置**连珠 26 种标准开局**的名字表与开局策略:

- **命名(显示)**:前三手(黑1、白2、黑3)形状命中即给出开局名,
  用于 UI 显示(前 5 手内与引擎搜索信息同栏)。
- **开局策略(前三手着法)**:trivial bestmove —— 开局域内
  位形直接给点、**不走搜索**(没有搜索统计可显示);第四手起完全
  回到搜索,搜索阶段不读开局库,也没有任何带估值的着法书。

## 协议

- 引擎导出(wasm C ABI,`src/api.rs`):
  - `ar_opening(ptr, len)` —— 用与 `ar_state` 同一份输入缓冲里的
    落点序列查前三手,返回 `1..=26`(直指 D1..D13 = 1..13、
    斜指 I1..I13 = 14..26),`0` = 未命中;
  - `ar_opening_name_ptr() / ar_opening_name_len()` —— 命中开局的
    UTF-8 名字(指针直指线性内存静态串,零拷贝;对应 AetherOthello
    的 `engineBookNamePtr/Len`);
  - `ar_book_enable(0/1)` —— 开局策略开关(默认开;关闭后前三手也
    走搜索,基准用,让前三手也走搜索)。
- Worker(`src/worker.js`):
  - `state` 回包新增可选字段 `opening: '花月'` —— 三手起命中才有,
    字段整局携带;旧 wasm 无此导出时字段缺省(UI 无感降级);
  - `think` 回包新增 `book: true/false` —— `true` 表示该着来自开局
    策略(无搜索,`depth`/`nodes` 为 0)。
- UI(`pages/app.js`):引擎搜索信息行(深度 / 节点 / 耗时 / 评分)
  前显示,盘面 ≤5 手(开局阶段)时冠以「开局库 · 花月 · 」,第 6 手
  起隐藏;策略着法没有统计,只标「开局库」,待第 3 手落定补上名字。

**匹配规则 = 纯形状**:前三手的相对位置(平移 + 8 对称不变)落在
26 表内即命中。不要求黑1 在天元 —— 偏心下的同型开局同样点名;
黑白次序是定义的一部分,换序不命中。与规则模式无关(无禁/有禁
都显示)。不足三手、序列非法、或形状书外 → 不命中。

## 来源与验证(2026-09-30 定稿)

开局名称与前三手形状是连珠界通用的事实性公开数据(日式命名体系,
RIF 采纳的 26 分类),没有借自任何软件开局库的内容。主表来源与
三重对拍:

1. **主来源** —— 台湾连珠教学网「開局」页
   (<https://587.renju.org.tw/open.htm>)的「26開局相對位置」图,
   两个 5×5 网格逐格解码(●=黑1,○=白2,字=该位黑3 的开局名):
   ```
   直接                間接
   ┼┼寒溪疏          ┼┼┼┼長
   ┼┼○花殘          ┼┼┼○峽
   ┼┼●雨金          ┼┼●雲恆
   ┼┼松丘新          ┼斜銀浦水
   ┼┼瑞山游          彗名明嵐流
   ```
2. **坐标对拍** —— 江湖定式文章(彭氏口诀流传版)的坐标样本
   寒星 H10 / 疏星 J10 / 花月 I9 / 雨月 I8 / 丘月 I7,与主来源
   解码结果 5/5 全部吻合(该文以白2 = H9 为直指基准,与本表同框)。
3. **命名规律自检** —— 「黑1、黑3 同线或同对角且中隔一格为星,
   其余为月」:直/斜各 5 星 8 月,26 个位置与名字后缀全部对上,
   零例外(`tests/opening.rs::table_shape` 固化此检查)。
4. **完备性对拍** —— 白2 ∈ 天元 8 邻点、黑3 ∈ 5×5 框内且不与
   前两手重合,共 8×23 = 184 个位形;26 开局正是它们在 8 对称下
   的完全分类(20 轨道 × 8 + 6 镜像/转置不动轨道 × 4 = 184)。
   `tests/opening.rs::orbit_consistency_exhaustive` 穷举 184 个
   位形:全部命中、同轨道同名、26 名全出现。
5. **名单与顺序对照** —— 台湾站 D1..D13/I1..I13 顺序与助记图
   (wuziqi123《五子棋26种开局助记图》,即彭氏口诀「寒星溪月疏星
   首……」)一致;直指/斜指 13+13 名单与中文百科类文章一致。

参考:gomokufive.com《Gomoku Openings》给出同套 26 名
(日文名 + 罗马字),其个别图示坐标与本表不同框(第二手画在
天元正东),换算后与本表同型。

## 开局策略(trivial bestmove)

开局位形直接给点、不走搜索(空盘给天元)。`src/opening.rs` 的
`policy_move` 里,前三手落在 26 开局域内的位形
直接给点、不进搜索:

| 盘面 | 策略着法 | 说明 |
|---|---|---|
| 空盘 | 天元 | 确定 |
| 一子 | 黑1 的盘内 8 邻点 | 白2,直指/斜指皆可 |
| 两子且白紧邻黑 | 黑1 的 5×5 区内空点 | 黑3,必成 26 开局之一 |
| 白2 不紧邻 / 已满三手 | —(None) | 书外位形回退搜索 |

选点在合法形状集合内**均匀随机** —— 26 开局都可能开出(实测白2
覆盖全部 8 邻点、黑3 撒满 5×5 区),开局库不携带任何估值,不存在
「按书选优」。随机源:wasm 用 `env.now`(worker / 测试 / 基准实例化
时都已提供),原生用固定种子(`policy_move_seeded` 供测试复现)。
搜索阶段(第四手起)不读开局库。

## 与 AetherOthello 开局书的异同

| | AetherOthello | AetherRenju |
|---|---|---|
| 数据 | 1,112 局面 + 精确估值 + 最佳着法(借自 Egaroucid) | 26 个开局名(公开事实数据),无估值 |
| 形态 | `book-openings.bin` blob(`@embedFile` + 名字池) | Rust 常量表(`src/opening.rs`,无 blob) |
| 匹配 | 规范化局面哈希(8 对称) | 前三手相对偏移(平移 + 8 对称) |
| 作用 | 命中出书内最佳着(值容差 + 加权随机)+ 显示 | 前三手开局策略(书域内均匀随机)+ 显示;搜索阶段不用书 |
| 通道 | think 回包 `book` / `name` | think 回包 `book` + state 回包 `opening` |
| 零拷贝名字 | `engineBookNamePtr/Len` | `ar_opening_name_ptr/len` |
